# Google Cloud 管理规则

## 核对顺序

1. **定位**：确认当前账号、项目 ID、资源全名、区域、环境和关联服务。
2. **取证**：读取实时配置、最近变更、监控与告警；记录控制台链接或命令及采集时间。
3. **评估**：说明影响对象、费用或权限变化、依赖关系、恢复方式和验证标准。
4. **执行与验证**：按已明确的授权范围操作；核对资源状态与业务可用性，并记录结果。

## 操作边界

- 只读查看和仓库内记录可直接进行。创建、删除、重启、扩容、变更网络、IAM、服务账号、账单或生产配置需先明确授权边界。
- 权限变更遵循最小权限和可追溯原则；不通过分享密钥或把凭证写入 Markdown 解决访问问题。
- 删除磁盘、快照、映像、bucket 或项目之前，先核实引用关系、备份和恢复路径；不能凭“空闲”提示直接删除。
- 控制台建议和告警是排查入口，不直接等同于已确认的故障或应执行的变更。
- 费用记录注明币种、计费期间、页面范围和采集时间；预测费用与实际账单分开。

## 文档边界

- 本目录保存项目级资源清单、治理规则和跨服务变化；具体应用部署、SSH、日志及事故细节留在对应子项目。
- 静态事实和动态快照分开；动态状态每次操作前重新核实，不能把旧 VM 名称、IP、计数或费用当作当前值。
- 重要结论要写明来源、日期、已确认事实、风险和下一步。不得保存密码、密钥、Token、Cookie、服务账号 JSON 或完整连接串。
