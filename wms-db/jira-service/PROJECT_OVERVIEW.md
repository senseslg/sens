# Jira 需求服务项目概览

## 目标与当前结论（2026-10-03）

用独立 Python/FastAPI 服务规范创建需求、汇总和定制导出，并通过 Jira 工作流关闭或标记不做。现有 Jira 7.12.0 REST API 已满足首版接入，不需要先升级 Jira，也不需要直接修改数据库。

服务版本 0.3.0，位于 `/Users/lingang/sens/wms-db/jira-service`，运行在用户本机 Mac；Jira 本体在 GCP `wms-db`。当前只是本机终端进程，未配置常驻服务或服务器部署。已有功能适合本机受控使用，不能据此认定已具备共享生产服务的运维条件。

## 能力与验证评估

| 能力 | 当前实现及证据 | 判断与边界 |
|---|---|---|
| 认证与项目字段 | `sens` Basic Auth 实测；项目、创建元数据、字段/解决结果目录可读；本地业务接口需 `X-API-Key` | 凭据已配置；浏览器登录不能替代 API 凭据 |
| 创建需求 | 默认预检查，提交需幂等键；真实 API 创建 CE-2629，读回核对标题、描述、经办人、报告人和状态 | 已完成实际建单；字段存在性/必填项由服务检查，值和权限由 Jira 最终校验 |
| 关闭/不做 | 查询当前工作流；只允许结束状态；状态预期、原因备注、解决结果和幂等校验 | 真实 CCSL-2679 预检查通过；提交仅模拟验证，尚未实际关闭需求 |
| 汇总 | JQL 分页，项目/状态/类型/经办人计数；显式报告截断 | 只统计返回条目，分页不是事务快照 |
| CSV | 自选字段/中文列名/全部 API 字段；UTF-8 BOM、复杂值 JSON、公式注入处理 | CCSL-2679 实测 1 行 57 列；与后台“所有域”的列和展示格式尚未逐项对齐 |
| 周报/月报 | 命令行脚本或接口按解决日期筛选，仅请求 7 个 API 字段并输出指定 8 列；原生 CSV 样本核对人员/项目；时间默认 UTC+7 | 2026 年九月实测 152 条；范围为账号可见的全部项目，接口可限定项目 |
| 本地验证 | 18 项模拟 Jira 测试通过；HTTP 与 Swagger 认证入口已检查 | 覆盖核心防重、超时、字段、CSV 和转换逻辑，不能代替所有项目工作流的端到端验证 |

查询默认 1000、最大 10000 条；导出遇到截断拒绝下载。创建或转换超时不自动重试；`pending/unknown` 防止盲目重复提交，仍缺少人工核对后的恢复流程。提交后读回失败或不匹配返回 `verified=false`，需核对 Jira 实际结果。

CE-2629 跟踪长期治理，说明中引用已解决的 CE-2626。范围包括 DEBUG/stdout、轮转与保留期、XXL-JOB 清理、POI 资源释放、Jenkins 配置固化及磁盘/inode 告警；真实生产修复状态由 [OTWMS 项目](../../otwms-server/PROJECT_OVERVIEW.md) 维护，建单不代表部署完成。

CCSL-2679 的关闭预检查快照为动作 `2`、目标状态 `6`（已关闭）、解决结果 `10001`（Won't Do）。这是该需求当时的工作流结果，不是所有项目的固定 ID。没有取消任何真实需求；开发关闭接口不等于授权关闭任意需求。

## 决策、风险与下一步

- 默认走 API；字段或工作流不支持时再用 Chrome 后台。创建前查重，提交后读回核对编号和关键字段。
- 用户导出偏好为 CSV（所有域）；全字段交付需标注“全部 API 字段”。周报/月报已确定精简 8 列，原生 CSV 样本核对通过，创建列按用户要求命名“创建时间”；不宣称全部 API 字段导出与后台全域等价。
- 实际关闭需用户指定编号与原因；提交前重新读取状态、动作和解决结果，保留原因备注，不删除需求。
- 私有配置权限 `600`，目录 `.local` 权限 `700`；凭据和防重库被 Git 忽略。后续导出默认保存到 `/Users/lingang/Downloads`，不进入仓库；旧 `exports/` 仍被忽略。服务权限仍受 Jira 账号权限影响。
- 复用评估：新增 [export_report.py](export_report.py) 作为月份/日期区间的命令行入口，调用现有报表 API；无需复制业务逻辑。暂不生成独立 Skill，理由与后续条件见 [Runbook 复用评估](RUNBOOK.md)。旧 CLI 仅作早期探测工具，日常操作优先本服务。
