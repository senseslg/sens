# 执行与记录约束

适用本目录及其后续脚本/Skill。每次继续先读 README、工作清单与最近实施记录。

## 逐项处理

1. 定位项目、资源全名、区域、环境、业务依赖和原清单编号。
2. 重新采集实时状态；证据标注 UTC+7 时间、采集窗口、单位、来源及缺失项。
3. 写出候选方案、净节省与一次性成本、业务影响、备份/恢复、停止阈值和验收标准。
4. 对生产写入、启停、删除、规格/配额/网络/IAM/账单变更，核对已有明确授权；未覆盖的部分提出具体可审核方案后再确认。
5. 一次只改一个可归因维度；核对业务与资源，观察相应高峰/夜间任务，再更新状态。
6. 每项结束评估复用价值；实际结果与证据写入实施记录，账单结果写入审核记录。

## 取证边界

- 旧快照、低 CPU、错误请求、未挂载、零节点均不能单独证明可删除或停用。
- 未知指标标“未采集”；不能用 0 代替失败/缺失。均值、小时 P95 和采样峰值分开。
- 数据库操作前读取对应服务记录，并应用本机 `db-ops-debug` Skill；避免大表全量 COUNT 和业务报文导出。
- 历史数据清理必须冻结截止时间、业务用途与批准范围；对象年龄不等于无访问，版本数不等于唯一文件数。
- BigQuery SELECT 也可能计费：先 dry-run，明确扫描上限；克隆/压测/迁移须先列出新增费用。
- 密码、Token、API key 值、私钥、Cookie、连接串、原始客户报文不落盘或回显。
