# 端口健康不等于应用就绪

适用于 Tomcat 等启动耗时较长的服务：发布脚本报告 PID、负载均衡探测通过后，页面仍可能超时。

## 三层验收

1. **进程与端口：** PID 存在且目标端口监听，只能说明进程已启动。
2. **HTTP 就绪：** 实例本机的无副作用路径在限定时间内返回预期状态，再核对公网路由和 TLS。
3. **业务可用：** 对实际业务的轻量只读场景验收；不能从登录页 200 推断全部 App 页面恢复。

2026-09-18 的 TMS 案例中，TCP/8080 已被 GCP 判为 `HEALTHY`，而本机 HTTP 仍持续超时；约十多分钟后登录页才可用。Google Cloud 官方说明：[TCP 检查默认只需建立连接，HTTP 检查则要求收到 200](https://docs.cloud.google.com/load-balancing/docs/health-check-concepts)。

建议在发布流水线中轮询真实 HTTP 就绪端点，设置合理总超时与失败退出码；健康检查路径须无副作用，并在应用初始化完成后才返回 200。变更负载均衡健康检查前，核对共享 URL map 中的其他主机规则和回滚方案。
