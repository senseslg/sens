## 佣金查询隔离试验

使用仅 Unix socket 的本机 MySQL 8.4.11、50 万条合成记录加边界样本，旧明细查询与 SQL `SUM` 对照。两个月查询连续跑 7 轮、取中位数；不含 Java HTTP 链路，不能外推生产延迟。

| 方案 | 两个月合计 | 返回行数 |
|---|---:|---:|
| 查明细后求和、原有单列索引 | 10.184 ms | 1,935 |
| SQL `SUM`、原有单列索引 | 3.050 ms | 2 |
| SQL `SUM`、联合索引 `(courier_code, is_deleted, commission_date)` | 2.756 ms | 2 |

聚合保留左闭右开日期窗口、软删除过滤及先合计再 HALF_UP 两位小数。7 组边界（含跨月/跨年、负数、空结果、零金额、软删除和大额精度）及两个月压测金额一致。联合索引在两个月均被使用，索引扫描候选总数从 2,007 降至 1,935；样本中增益较小，优先验证 SQL 聚合，索引上线需用代表性分布复核收益及 DDL 成本。试验金额列为非空；还需核实线上列约束、如允许 NULL 时的既有行为，以及真实 Mapper/序列化结果。

仓库 test/prod 数据库端点不同，不等于公司 UAT 运行时已核实。本次未连公司 UAT 或生产，临时实例与合成数据已移除。仅留验证记录，不新增脚本或 Skill。
