# OTWMS GCP Inspection Tool Roadmap

## 工具定位

来源摘要提到 Python 工具 `check_gcloud_otwms_disk.py`，用于自动发现生产实例并执行 OTWMS 基础巡检。

本次建档未找到脚本文件，因此下述版本状态来自摘要，不代表代码已复制或验证到本仓库。

## v1.0.0 — 摘要记录的现有能力

- 自动查找 `otwms-group-*` 实例。
- 通过 SSH 登录。
- 执行 `df -h`。
- 检查根目录占用。
- 检查 Java 进程。
- 检查 deleted file handle。
- 检查主要日志。

## v1.1.0 — 计划

为巡检结果增加自动等级判断：

- `OK`：状态正常，无需操作。
- `WARNING`：存在增长趋势或接近阈值，需要人工关注。
- `CRITICAL`：达到危险阈值或关键进程异常，需要立即响应。

阈值尚未在来源资料中定义，实施前需要明确：

- 磁盘使用率阈值。
- 日志文件大小与增长速度阈值。
- Java 缺失或多进程时的判断规则。
- Deleted file handle 的严重程度规则。
- SSH、权限或命令失败如何分类。

## v2.0.0 — 计划中的修复模式

计划支持 `--fix`，摘要描述的目标能力包括：

- 停止 BladeX / Java。
- 截断主要日志。
- 通过 `startup.sh` 重启应用。
- 自动验证恢复结果。

## v2.0.0 安全门槛

在实现或启用 `--fix` 前，至少需要满足：

- 默认只读，必须显式传入修复参数。
- 动态发现实例后仍要求显示目标并确认。
- 精确识别 BladeX 进程，不能宽泛终止所有 Java。
- 操作前记录磁盘、进程、日志和应用状态。
- 明确日志文件白名单，禁止任意路径截断。
- 重启失败时返回非零状态并保留诊断信息。
- 修复后重新执行完整巡检和业务可用性检查。
- 保存前后状态和执行结果，便于审计与复盘。
