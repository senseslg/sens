# 工作项生命周期

用于管理一个需要持续推进的项目、任务或协作事项。

## 状态

| 状态 | 含义 |
|---|---|
| `proposed` | 已提出，但目标或是否执行尚未确认 |
| `active` | 已确认并正在推进 |
| `waiting` | 等待用户、同事、外部系统或指定时间 |
| `blocked` | 存在明确阻塞，当前无法继续推进 |
| `completed` | 完成标准已经满足 |
| `cancelled` | 明确决定不再继续 |
| `archived` | 已结束且无需出现在当前工作视图 |

`waiting` 不等于 `blocked`：正常等待预期中的反馈或时间点时使用 `waiting`；只有无法继续且需要解除条件时才使用 `blocked`。

## 接收工作项

1. 写清目标和期望结果。
2. 确认范围、优先级、时间要求和授权边界。
3. 定义完成标准。
4. 识别已有资料、依赖和风险。
5. 需要跨天推进时，从项目模板创建主记录。

## 推进工作项

- 每次工作前读取项目主记录。
- 优先更新当前状态和下一步，不把正文变成操作流水。
- 新决定记录日期、内容和必要的依据。
- 行动项尽量包含负责人；没有明确期限时不要虚构日期。
- 发现阻塞时写清解除阻塞所需的具体条件。

## 完成工作项

只有在完成标准实际满足时标记 `completed`，并记录：

- 交付结果或文件位置
- 验证方式和结果
- 未纳入范围的事项
- 是否存在后续维护或复盘需要

## 归档

- 完成或取消后，不立即删除记录。
- 当内容不再参与当前工作时标记 `archived`，必要时未来再建立 `records/archive/`。
- 归档前确保总览和其他项目文件不再引用过期状态。
