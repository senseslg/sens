## 带宽换算

`3 Mbps` 理论最大吞吐约为：

```text
3 ÷ 8 = 0.375 MB/s
```

不考虑 TCP、TLS 和并发开销时：

| 资源大小 | 理论最短传输时间 |
|---|---|
| 500 KB | 约 1.3 秒 |
| 1 MB | 约 2.7 秒 |
| 2.4 MB | 约 6.4 秒 |
| 5 MB | 约 13.3 秒 |

本地生产构建的 `.next/static` 约 `2.4 MB`，其中发现一个约 `514 KB` 的 JavaScript chunk。浏览器通常不会每次下载全部资源，且压缩与缓存会改变实际大小，但这个量级足以说明 3 Mbps 对冷启动和首次访问不友好。

## 2026-07-15 只读入口检查

### 公网 IP 默认站点

对用户提供的公网 IP 做了只读 HTTP 测试：

- 端口 80：Nginx `1.18.0` 默认欢迎页，HTTP 200。
- 连接时间约 `37 ms`，TTFB 约 `75 ms`。
- 端口 3001：外部连接超时，可能被安全组或防火墙保护，也可能未对公网监听。
- IP 默认站点没有反向代理到 MallGoGo，说明应用依赖域名 Server Block。

### MallGoGo 真实域名

- `www.cel-mall.com` 和 `cel-mall.com` 均解析到目标 ECS。
- `/` 返回 302 并跳转至 `/en`。
- `/en` 返回 HTTP 200，服务端标识为 Nuxt。
- 单次外部测试：连接约 `54 ms`、TLS 约 `104 ms`、HTML TTFB 约 `0.29 s`；这些数据会随客户端位置和时间变化，仅作为基线。
- gzip 后 HTML 约 `37 KB`；未压缩正文约 `195 KB`。
- HTTPS 当前使用 HTTP/1.1。

## 当前判断

公网 IP 默认页和真实域名的 HTML TTFB 都不算异常，慢体验更可能发生在框架服务、JavaScript、图片和后续 API 阶段。更重要的是，真实域名当前运行 Nuxt，并非已检查的本地 Next.js 项目。
