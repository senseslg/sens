# Finance Recording Rules

## 单笔账目必填字段

| 字段 | 要求 |
|---|---|
| Transaction ID | 唯一且稳定，不重复使用 |
| Date | 业务发生日期，格式 `YYYY-MM-DD` |
| Entity | 账目所属主体代号 |
| Account | 资金账户或往来账户代号 |
| Type | 收入 / 支出 / 应收 / 应付 / 转账 / 调整 |
| Category | 使用受控分类，不随意新增近义分类 |
| Counterparty | 对方代号或经批准的简称 |
| Original amount | 原币金额，收入和支出符号规则需统一 |
| Currency | ISO 币种代码或经确认的统一代码 |
| Exchange rate | 非本位币时必填，并记录来源与日期 |
| Base amount | 按统一规则换算后的本位币金额 |
| Business reference | 订单、发票、合同、报销或批次编号 |
| Evidence status | 已附 / 待补 / 不适用 |
| Reconciliation status | 未核对 / 已核对 / 有差异 |
| Owner | 录入或跟进负责人 |
| Notes | 只记录必要说明，不放密码或敏感身份信息 |

## 记录原则

1. 一笔业务只记录一次，不能因出现在多个来源中而重复计入。
2. 银行或平台内部转账不计入收入或支出，应使用“转账”类型匹配两端。
3. 应收、收款、应付和付款分开记录，避免只看现金流而遗漏债权债务。
4. 原币金额永不覆盖；汇率变化只影响换算或期末重估记录。
5. 已关账期间的更正使用调整分录，不直接静默修改历史数字。
6. 未确认记录标记状态，不为了让余额相等而制造无依据调整。
7. 删除记录必须保留原因和审批痕迹；优先作废或冲销。

## 凭证规则

- 每笔重要收支应关联发票、收据、合同、银行回单或平台记录。
- 仓库只保存凭证索引、脱敏摘要或受控存储位置，不直接提交包含完整账号、证件号和个人信息的文件。
- 文件名建议使用日期、交易编号和凭证类型，不包含完整账户号码。
- 缺失凭证进入待补清单，并在月结前处理或获得书面批准。

## SMS 报销专项规则

- Plasgate 充值周期说明的输入、计算、精度和中英文模板见 [`SMS_REIMBURSEMENT_RULES.md`](SMS_REIMBURSEMENT_RULES.md)。
- 报销记录至少关联充值/支付日期、实际使用期间、短信总量、平台费用、币种、账单/发票状态和审批状态。
- 预充值付款与短信实际消耗分别记录并使用同一业务关联编号；不得把未消耗余额直接计入本期短信费用。
- 平均单价和较上次变化属于派生指标，必须由本次与上一次实际支付记录重新计算，不作为独立入账依据。

## 导入与去重

- 每次导入记录来源文件、期间、行数、金额合计和导入时间。
- 使用来源流水号、账户、日期、金额和对方组合进行重复检查。
- 导入前保留原始文件只读副本；清洗后的数据另存，不覆盖原文件。
- 导入后核对期初余额、期间发生额和期末余额。

## 审核状态

```text
draft → reviewed → reconciled → closed
```

- `draft`：已录入但未审核。
- `reviewed`：字段、分类和凭证已审核。
- `reconciled`：已与外部账单或业务系统核对。
- `closed`：已纳入月结，修改需要调整记录。
