# CE Finance Overview

- 状态：`proposed`
- 负责人：待确认
- 建立日期：`2026-07-22`
- 最近更新：`2026-07-22`

## 目标

建立可信、可追溯、可对账的 CE 财务工作记录，统一管理收入、支出、应收、应付、报销、账户余额、凭证和月度汇总，并让异常差异与后续行动能够持续追踪。

## 完成标准

- [ ] 明确管理主体、币种、账户和账目起始日期。
- [ ] 建立统一的收入、支出、应收、应付和资金转移分类。
- [ ] 明确每笔账目的必填字段和凭证要求。
- [ ] 完成现有账目来源盘点与期初余额确认。
- [ ] 建立月度银行/现金/平台/业务账目对账流程。
- [ ] 建立应收应付账龄、异常差异和逾期行动清单。
- [ ] 建立月度汇总、审核、锁定和更正机制。
- [ ] 明确敏感财务资料的访问、保存和备份规则。

## 范围

### 默认包含

- 收入与回款。
- 采购、费用与付款。
- 应收账款与应付账款。
- 员工借款、预支与报销。
- 银行、现金、支付平台和内部资金转移。
- 多币种金额、汇率和换算依据。
- 发票、收据、合同及其他凭证状态。
- 月度余额、损益摘要、差异和待办事项。
- Plasgate 短信平台按实际充值周期发生的支付、消耗和报销说明。

### 暂未确认

- CE 对应的法律主体和业务范围。
- 是否包含个人账目、公司账目或多个公司主体。
- 是否需要税务申报、工资、固定资产或库存会计。
- 是否与 CCSL、OTWMS、MallGoGo 等业务系统自动同步。
- 账目使用 Excel、Google Sheets、数据库或专业财务系统承载。

## 当前状态

目前只确认项目用途为账目管理，尚未收到完整账户、流水或报表。首版已建立通用记录框架和 Plasgate 短信充值周期报销模板；支付在余额使用完后发生，默认与上一次支付记录比较，不使用自然月环比。模板不代表任何记录已完成审批或正式入账。

## 风险与依赖

- 主体、币种和会计期间未确认前，金额不能可靠汇总。
- 重复导入、漏记、错币种和内部转账重复计入收入/支出是主要数据风险。
- 未附凭证或未核对记录不能直接视为正式入账。
- 财务数据属于高敏感信息，需要明确访问权限、备份和外部共享边界。
- 税务和法定报表必须由适用司法辖区的专业人员复核。
