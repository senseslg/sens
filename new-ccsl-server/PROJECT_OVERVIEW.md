## 当前状态

已根据 2026-07-21 生产事故记录建立首版运行基线。CCSL 生产 Java 应用使用 HikariCP、MySQL 兼容的阿里云数据库与 Spring Redis Cache；应用监听 `8080`，当前通过脚本与 `nohup` 管理，未接入 systemd。

2026-07-21 生产环境两次出现 Hikari 连接池耗尽和 504。第二次故障的线程栈显示大量线程争用同一个 `RedisCache` 锁，同时等待数据库连接。当前主要根因判断为缓存锁竞争与事务范围共同延长连接持有时间，而不是数据库实例连接数耗尽或整体慢查询阻塞。服务已通过重启恢复，但永久修复尚未完成。

2026-07-22 已通过 SSH 完成新服务器首轮只读盘点。服务器确认为阿里云 ECS、Ubuntu 24.04.3 LTS、2 vCPU、14 GiB 内存；生产和 UAT Java 应用分别监听 `8080` 与 `8081`，Nginx 已按域名代理对应端口。Nginx、Docker 和 Fail2ban 运行正常。

同日 Jenkins 更新 `/home/engineer/prod/backend/ccsl-prod.jar` 后，新生产进程按产物更新时间启动并在 `8080` 提供服务。本机入口和生产 HTTPS 域名均返回 200，日志中未发现应用启动失败、Hikari 获取超时或 OOM。该结论确认发布和服务入口成功，不等同于登录及关键业务链路已经验收；详见 [部署验证记录](DEPLOYMENT_2026-07-22_JENKINS.md)。

已将本次实际使用的服务器基线和发布验证流程固化为 [`scripts/`](scripts/) 下的 Python 工具。后续优先直接运行脚本并保存脱敏结果；只有脚本无法覆盖的新问题才临时执行命令，验证稳定后再回写脚本。

2026-07-22 已为远端 `sens` 用户配置并验证 SSH 公钥认证，后续只读脚本可以免输服务器密码运行。该变更不代表服务端密码登录已关闭，SSH 加固状态仍需单独核对。

公钥配置完成后已端到端运行 `server_baseline.py` 和 `verify_deployment.py`：两个脚本均以退出码 `0` 完成，生产发布验证结果为 `PASS`。

## 风险与依赖

- 事故已复发过一次，单纯重启无法避免再次耗尽连接池。
- 生产代码、Hikari 参数和事故 jstack 尚未在本项目中直接审查。
- Redis Cache 锁竞争可能同时放大线程池、连接池和 TCP 连接压力。
- 慢 SQL、`cost` 死锁和 RDS 连接中断不是当前主要根因，但仍可能放大事故。
- 未确认现有备份、回滚、监控和生产变更窗口。
- Java 启动参数包含明文敏感配置；不得再使用会输出完整命令行的盘点命令，相关凭证需要轮换。
- `8080`、`8081`、`9000` 等端口在主机上监听所有网卡；公网可达性仍需结合云安全组和主机防火墙验证。
- 系统提示存在待安装更新并需要重启；变更前必须安排维护窗口和回滚验证。
- 任何凭证、密钥和完整连接串都不能进入版本库。
